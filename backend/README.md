## Architecture

Routes stay thin; business logic lives in a service layer; each external provider gets its own client:

```text
API route  →  service layer  →  database (SQLAlchemy) or external client
```

```text
app/
├── api/routes/     Thin FastAPI routers — one file per resource
├── services/       Business logic (validation, orchestration, persistence)
├── clients/        External provider clients (CoinGecko, CryptoPanic, OpenRouter)
├── models/         SQLAlchemy ORM models
├── schemas/        Pydantic request/response schemas
├── core/           Config, security (JWT/bcrypt), caching, constants
└── db/             Engine, session, declarative base
```

## Setup

```bash
python -m venv venv
./venv/Scripts/activate        # Windows
# source venv/bin/activate     # macOS/Linux
pip install -r requirements.txt
cp .env.example .env
```

Requires a local PostgreSQL instance matching `DATABASE_URL` in `.env`:

```bash
createdb crypto_advisor
alembic upgrade head
uvicorn app.main:app --reload
```

The server starts at http://localhost:8000 — interactive API docs at `/docs`.

## Environment variables

Full list with descriptions in [`.env.example`](.env.example). Never commit a real `.env`.

| Variable | Required | Notes |
|---|---|---|
| `DATABASE_URL` | Yes | PostgreSQL connection string |
| `JWT_SECRET` | Yes | Long random string — never reuse the placeholder |
| `JWT_ALGORITHM`, `JWT_EXPIRE_MINUTES` | No | Defaults provided |
| `CORS_ORIGINS` | Yes | Comma-separated allowed frontend origins |
| `COINGECKO_API_KEY` | No | CoinGecko's free demo tier works keyless |
| `CRYPTOPANIC_API_KEY` | No | Without one, news falls back to static content |
| `OPENROUTER_API_KEY`, `AI_MODEL` | No | Without a key, the AI insight falls back to a safe static message |

## Database

Four tables, managed with Alembic:

```text
users            1 ──── 0..1  user_preferences
users            1 ──── 0..*  daily_insights
users            1 ──── 0..*  content_feedback
```

Key constraints: `UNIQUE(users.email)`, `UNIQUE(user_preferences.user_id)`, `UNIQUE(daily_insights.user_id, insight_date)`, `UNIQUE(content_feedback.user_id, section_type, content_key)`, `CHECK(content_feedback.vote IN (-1, 1))`.

```bash
alembic upgrade head                                    # apply all migrations
alembic revision --autogenerate -m "describe change"    # after changing a model
```

Always review an autogenerated migration before applying it — see [../Skills/design-database-schema/SKILL.md](../Skills/design-database-schema/SKILL.md) for the full design rules.

## API reference

All routes are prefixed with `/api` except `/health`. Full schemas live in `app/schemas/`.

| Method | Path | Auth | Description |
|---|---|---|---|
| GET | `/health` | — | Liveness check |
| POST | `/api/auth/signup` | — | Create an account |
| POST | `/api/auth/login` | — | Log in, receive a JWT |
| GET | `/api/auth/me` | ✓ | Current user |
| GET | `/api/preferences/options` | — | Available assets / investor types / content types |
| GET | `/api/preferences/me` | ✓ | Current user's saved preferences |
| PUT | `/api/preferences/me` | ✓ | Save preferences, completes onboarding (atomic) |
| GET | `/api/market/prices` | ✓ | Prices for the user's selected assets (CoinGecko) |
| GET | `/api/market/news` | ✓ | Personalized market news (CryptoPanic, fallback-aware) |
| GET | `/api/insights/daily` | ✓ | Today's AI insight — generated once per user/day, then reused |
| GET | `/api/memes/random` | — | A random crypto meme |
| PUT | `/api/feedback` | ✓ | Upsert a thumbs-up/down vote (never a duplicate row) |
| GET | `/api/feedback/me` | ✓ | Current user's saved votes |

## Security

- Passwords hashed with `bcrypt`, never logged or returned in any response.
- JWT access tokens: signature, expiration, type, and subject are all validated on every protected request.
- The authenticated user is always loaded from the token — a frontend-supplied `user_id` is never trusted as identity.
- Generic error messages on failed login (never reveals whether the email exists).
- External requests (CoinGecko, CryptoPanic, OpenRouter) run through the backend only, with finite timeouts and controlled retries — a failing optional provider degrades to a labeled fallback instead of breaking the dashboard.
- Refuses to start in production (`ENVIRONMENT=production`) if `JWT_SECRET` is still the insecure default — fails loudly rather than booting with a forgeable secret.
- `/api/auth/login` and `/api/auth/signup` are rate-limited per client IP (10 attempts / 5 min, 5 signups / hour) to blunt brute-force and account-spam attempts — see `app/core/rate_limit.py`.

## Testing

```bash
./venv/Scripts/pytest   # Windows
# pytest                # macOS/Linux
```

Covers `/health`, database constraints (unique emails, one preference per user, one daily insight per user/date, valid vote values, cascading deletes), Pydantic validation, authentication (signup, login, JWT validation, protected endpoints), onboarding (validation, atomic save, upsert, per-user isolation), the CoinGecko/CryptoPanic clients (error handling, cache, fallback, personalization), the daily AI insight (grounding, prompt-injection containment, safety-phrase rejection, daily reuse, non-persisted fallback), the meme endpoint, and feedback (upsert, ownership, content-key validation, cross-user isolation).

Tests requiring a real database (auth, preferences, market/insight routes) are skipped automatically if `DATABASE_URL` isn't reachable. Provider-client and service-layer tests never touch a live network — mocked at the `httpx` transport level or via fake provider clients.
